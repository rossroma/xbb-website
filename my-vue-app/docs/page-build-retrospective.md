## 问题记录

### 问题 1：图片资源缺失（✅ 已修复）

**描述**：新页面中所有图片路径指向的文件不存在，导致页面展示时图片区域为空白。

**修复**：创建 8 个 SVG 占位图（`public/images/customer/*.svg`），每个占位图包含板块名称标注、建议尺寸和「待替换」标识。数据文件路径同步更新为 `.svg`。

---

### 问题 2：路由路径不符合规范（✅ 已修复）

**描述**：最初使用 `/customer` 作为路由路径，但 `routePaths.ts` 中定义客户管理页面的路径为 `/kehuguanli`。

**修复**：将 `router.ts` 中的路由路径从 `customer` 改为 `kehuguanli`。

**教训**：新增页面时，必须优先查阅 `src/client/data/routePaths.ts` 中定义的路径规范，而非自行命名。

---

### 问题 3：新增业务组件未在 UiKit 中注册（✅ 已修复）

**描述**：5 个新业务组件（ProductHero、ProductShowcase、TabFeatureShowcase、FeatureCardGrid、FinalCTA）未在 `UiKit.vue` 中展示。

**修复**：

- 在 `categories` 数组的 Business 组件分类中添加 5 个新条目
- 添加对应的 Demo 展示区域（含使用规范说明）
- 添加导入语句和 Demo 数据
- 更新现有 Layout 和 UI Kit 组件的 section ID 偏移

**教训**：新增业务组件后，必须同步在 `UiKit.vue` 中注册展示，确保组件可被团队发现和复用。

---

### 问题 4：TabFeatureShowcase 类型错误（✅ 已修复，实现阶段）

**描述**：`vue-tsc` 报 `TS2532: Object is possibly 'undefined'`，因为模板中直接使用 `tabs[activeTab]` 访问数组，TypeScript 无法推断索引一定有效。

**修复**：添加 `computed` 属性 `currentTab`，模板中通过 `v-if="currentTab"` 守卫后再访问。

**教训**：Vue 模板中访问 `ref<number>` 索引的数组元素时，TS 严格模式会报可能的 undefined。最佳实践是使用 `computed` 包装。

---

### 问题 5：业务组件样式反复调整，流程混乱

**描述**：新增的业务组件（TabFeatureShowcase）样式与预期差距大，调样式过程中经历了 3 轮交互反馈才达到满意效果。样式调整穿插在页面添加流程中，导致流程冗长、焦点分散。

**影响**：单组件样式调整耗时约占本次总流程的 40%，远超代码实现本身。

**建议改进**：

- `/page` 流程中，应在「组件盘点」阶段输出组件的视觉规格（配色、间距、动画等），让用户一次性确认
- 或者将样式调整独立为 `/component` 流程的后续步骤，不在 `/page` 流程中处理
- 新组件应先提供低保真 HTML 线框图预览，用户确认样式方向后再编码

---

### 问题 6：端到端自测后开发服务器被关闭

**描述**：每次使用 Browse 工具进行可视化自测后，`pkill -f "vite"` 会关闭开发服务器，且不会自动重启。用户需要手动执行 `pnpm dev` 重新启动服务。

**影响**：每次自测完成后，用户需要手动重启服务才能继续在浏览器中查看页面。

**建议改进**：

- 自测完成后，检查是否有正在运行的 vite 进程，如果有则不 kill
- 或者 kill 后自动执行 `pnpm dev` 重启服务
- 在复盘文档中建立检查清单：每次对话结束前确认 `pnpm dev` 是否在运行

**描述**：`vue-tsc` 报 `TS2532: Object is possibly 'undefined'`，因为模板中直接使用 `tabs[activeTab]` 访问数组，TypeScript 无法推断索引一定有效。

## 2026-07-24 — 流程优化：基于本次复盘的结构性改进

### 优化决策

基于本次客户管理页面构建中暴露的 6 个问题和 5 个待完善项，对 `/page` 和 `/component` 流程进行了结构性重构。

### 核心变化

#### 1. 彻底解耦：组件创建从 `/page` 中完全移除

**旧流程问题**：`/page` 流程中包含组件盘点、缺失检查、引导创建组件等步骤，导致页面组装和组件创建混在一起。本次实践中，5 个业务组件的样式调整占 40% 时间，严重拖慢页面组装进度。

**新流程**：`/page` 是纯组装流程，不涉及任何组件创建。用户必须明确指定每个板块对应的已有组件（板块 → 组件映射）。组件不存在则拒绝执行。

**严格顺序**：先 `/component`（逐个精细打磨组件）→ 后 `/page`（纯组装页面）。

#### 2. 参考图门禁

**旧流程问题**：文字描述样式，AI 靠猜测实现，导致 3 轮以上反复调整。这是本次流程中最大的效率杀手。

**新流程**：`/component` 和 `/page` 均新增参考图门禁。无参考图（设计稿/截图/草图/Pinterest）→ 拒绝执行。参考图直接锚定视觉目标，消除「AI 脑补」带来的反复调整。

#### 3. `/component` 流程强化

| 新增/强化                           | 来源               |
| ----------------------------------- | ------------------ |
| 参考图门禁（Phase 0）               | 问题 5             |
| UiKit 注册从步骤升级为门禁          | 问题 3             |
| TS 数组访问规范（computed 包装）    | 问题 4             |
| 图片资源检查 + 占位图自动生成       | 问题 1 + 待完善 #1 |
| 复用度标注（高/中/低）              | 待完善 #2          |

#### 4. `/page` 流程精简

| 新增/强化                               | 来源               |
| --------------------------------------- | ------------------ |
| 页面参考图门禁（Phase 0）               | 待完善 #3          |
| 板块 → 组件映射（用户指定，非 AI 盘点） | 核心重构           |
| 路由规范查阅（routePaths.ts）    | 问题 2             |
| 图片资源检查 + 占位图自动生成           | 问题 1 + 待完善 #1 |
| 可视化验证后保持 dev server 运行        | 问题 6             |

#### 5. 核心铁律更新

- **铁律 #8**：新增「参考图门禁」和「UiKit 注册门禁」为不可跳过的强制步骤
- **铁律 #9**：从「组件未就绪，禁止创建页面」强化为「先组件，后页面 — 严格顺序，不可颠倒」
- **新增铁律 #13**：创建组件和页面必须提供参考图
